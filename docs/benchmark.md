# Проверка на открытых макетах

Генератор вёрстки прогнан на 5 открытых Figma-файлах с GitHub (14 фреймов, от 2 до 497 слоёв)
и на эталонном макете DS Builder (11 фреймов) — выгрузке нашим плагином из настоящей Figma.
Воспроизвести: `cd packages/bench && npm install && npm run bench` (скачает файлы, шрифты из npm,
соберёт и проверит; результат — `.bench/summary.md`).

| Источник | Что это |

| `etalon/ds-builder-landing` | **Эталонный макет**: лендинг DS Builder (1440 и 390), компоненты Button, Nav Link, Input, Badge, Feature Card, Metric, Step, Section Heading и страница «Трудные случаи» (цветовые стили вместо переменных, текст с двумя стилями, переопределения в экземплярах, градиент на переменных, прозрачность на переменной, кегль и обводка на переменных, тени без стиля, скрытый слой). Всё на Auto Layout, цвета, отступы и радиусы — переменные, тексты и тени — стили. Пакет из плагина, PNG-эталоны — из Figma. На таком макете вёрстка обязана идти потоком без координат. |

Столбцы «Auto Layout → flex / по геометрии / absolute» — сколько контейнеров каким способом свёрстано.
Каждый прогон собирает и `html/` с общим CSS компонентов (`css/components.css`: `.button`, `.button--secondary`,
`:hover`/`:active`/`:disabled` из вариантов State) и проверяет, что каждая страница рендерится так же, как рабочая
вёрстка, — на всех макетах совпадает. На эталоне: button ×16, feature-card ×14, metric ×7, step ×7, nav-link ×6, input ×5,
section-heading ×4, badge ×3.
На эталонном макете — ни одного `absolute`: геометрия совпала до 0 px, всё расхождение — сглаживание текста
(Figma и Chrome рисуют буквы по-разному: 1–3% площади текстовых слоёв). Поэтому текст проходит, если
расхождение не больше 0.5% экрана **или** 4% площади текстов: раньше маленькие фреймы проваливались
(подпись 12 px на Badge — 1% экрана). Проверка на Desktop, что настоящие ошибки шрифта не проходят:
вес 400→500 — 4.8% площади текстов, кегль 16→15 — 4.7%, межбуквенный +0.3px — 9.6%, Arial вместо Inter — 8.8%.
До исправления обводки в раскладке (`strokesIncludedInLayout`) главные экраны уходили в `absolute`:
обводка 1 px сдвигала всё содержимое карточек и полей.
`absolute` остаётся только там, где слои действительно перекрываются (декор, бейджи, кнопки поверх картинок).

У шаблона Physionic в репозитории лежат SCSS-переменные автора (`assets/sass/abstract/_variables.scss`).
`ds-build analyze` по макету (без доступа к SCSS) дал **14 из 14** совпадений:

| Что | Анализ | Автор |

| text-secondary | `#737373` | `$second-text-color` |

| accent | `#2DC071` | `$secondary-color-1` |

Также: 18 цветов макета → 13 токенов (`#F9F9F9` и `#F6F6F6` слиты с `#FAFAFA`, серые обводки — в `gray-200`),
типографика h1 58 / h2 40 / h3 30 / h4 24 / h5 20 / body 14 на Montserrat, обзорная страница INDEX распознана
как масштабированная копия. Аудит нашёл реальные нарушения WCAG: синий `#23A6F0` с белым — контраст 2.69.

## Как менялся результат на настоящих эталонах (v2.1 / v3)

Каждый прогон находил конкретную причину, она исправлялась в коде, затем прогон повторялся.

| Шаг | v2.1 | v3 | Что нашли и исправили |
|---|---|---|---|
| 1. Первый прогон | 12.72% | 8.40% | — |
| 2. Векторы из `.fig` | 4.52% | 2.65% | Карта мира — векторы; конвертер `.fig` научился собирать SVG из геометрии путей. **Ошибка генератора:** прямоугольник со свечением (`LAYER_BLUR`) вбирался в фон кнопки вместе с размытием — размывался текст. Теперь размытые слои в фон не превращаются. |
| 3. Группы | 2.65% | 2.03% | В `.fig` группы хранятся как фреймы с `resizeToFit` и **не обрезают** содержимое — обводка кольца глобуса была отрезана. |
| 4. Цвет картинок | 1.98% | 1.68% | Figma показывает картинки без цветового профиля, браузер — с ним (красный бледнел). Программа убирает ICC-профили из PNG/JPEG и рендерит в sRGB. |
| 5. Автодоработка | **0.38%** | **0.21%** | Оставшиеся расхождения — метрики шрифта (ширина строк в браузере и Figma). Программа сама подбирает межбуквенный интервал и сдвиг строки для слоёв с наибольшим расхождением и оставляет поправку, только если она ближе к эталону. |

Ещё одна ошибка найдена на макете Discord: у копий одного компонента совпадали ID, и проверка геометрии сравнивала их с одним слоем (сдвиг до 904px). Исправлено в конвертере.

## Что осталось и почему критерий раздельный

После автодоработки 99% остаточных пикселей — внутри текста: отдельные пары букв (кернинг) у Figma и Chrome
растеризуются чуть по-разному, и одна поправка интервала на весь блок это полностью не убирает.
Поэтому критерий pixel perfect:

- **геометрия** каждого элемента ±0.5px — строго;
- **пиксели вне текста** (цвета, фигуры, картинки, тени) — не больше 0.1%;
- **пиксели текста** — не больше 0.5% (настраивается `--text-threshold`).

Сдвиг текстового блока этим допуском не прячется: автодоработка запускается при любом заметном расхождении в тексте.
Проверено: заголовок, сдвинутый в макете на 2px, автодоработка вернула на место (0.159% → 0.000%).

## Компоненты, фреймворки, адаптивность

- **React и Vue** (`--framework react,vue`): страницы, отрендеренные на сервере (`renderToStaticMarkup`,
  `@vue/server-renderer`), совпадают с HTML-версией символ в символ на fixture, Physionic, HackRPI и Discord.
- **Адаптивность**: Physionic «Template / Desktop» (1440) и «Template / Mobile» (414) собраны в одну страницу;
  на 414 и 1440 она совпадает со своими макетами (pixel diff 0, геометрия полная). Между ширинами оба макета
  «тянутся»: на 927, 1439, 1620 и 1800 px нет прокрутки, текст не налезает и не вылезает за край, фоны секций —
  на всю ширину. Первая версия растягивания у мобильного макета сдвигала 36 элементов на его же ширине
  (блок шире экрана по центру): это поймала проверка, правило исправлено. В Discord «iPhone 14 - 1» и «Android Large - 1» не объединились:
  у них разные тексты, это разные экраны.

Пакет из 40 фреймов 1440px (макеты HackRPI с эталонами Figma и автодоработкой), машина с 2 ядрами:

| Сборка | Время |
|---|---|
| 1 фрейм за раз (`--jobs 1`) | 150 с |
| 2 фрейма одновременно (по умолчанию на 2 ядрах) | 108 с |
| повторная сборка, макет не менялся | **0.8 с** (40 из 40 из кэша) |
| повторная сборка, изменены 2 фрейма | **2 с** (38 из 40 из кэша) |

Оценка для файла на 300 фреймов: первая сборка — около 13 минут на 2 ядрах и около 7 на 4;
после правок в макете — секунды плюс время на изменённые фреймы. Плагин выгружает такой файл частями
по 25 фреймов (страница Figma не разрывается), окно программы принимает все части сразу.

## Windows

Те же эталоны HackRPI, сверка на Windows (GitHub Actions, Chrome stable): v2.1 — 1.912% → **0.371%**,
v3 — 1.645% → **0.201%** после автодоработки, геометрия полная. Как на Linux (0.381% / 0.207%).
Флаги Chrome для текста (`--text-contrast`, `--text-gamma`, `--disable-font-subpixel-positioning`) результат не меняют.

## Реальный макет пользователя (дашборд, 279 слоёв)

Первый прогон у пользователя: геометрия 279/279, но pixel diff 28.5%. Причины и исправления:
- фрейм без заливки → эталон с прозрачным фоном; сравнение теперь на белом: 28.5% → 1.8%;
- текст с интерлиньяжем меньше «стойки» body (12/14) съезжал вниз на 2–3px: 1.8% → 1.6%;
- пунктирная обводка рисовалась сплошной; пустой текст получал `font-family: "undefined"`.

## Векторы: файл или в странице

Небольшие SVG (иконки, булевы операции) теперь вставляются в страницу, а не подключаются картинкой.
Сравнение тех же страниц Physionic в двух режимах: Mobile — 1 пиксель разницы, Desktop — 149 из 7.2 млн
(сглаживание иконок на дробных координатах: картинка выравнивается по пикселю, встроенный SVG — нет).
На эталонах HackRPI результат не хуже: v3 0.209% → 0.207%. Маски CSS (иконка как `mask-image`) проверены и
отвергнуты: при открытии страницы с диска (`file://`) браузер их блокирует.

## Скорость фреймов, которые не сходятся

Автодоработка (подбор поправок) — самая дорогая часть проверки: ~4–5 с на фрейм 1440px против ~1 с на рендер и
сравнение. Раньше она запускалась на каждой запасной попытке раскладки (flow → до 4 гибридных → absolute), то есть
до 6 раз на фрейм, который не сходится. Теперь — на первой попытке и один раз на выбранном запасном варианте.
Замер: 2 фрейма HackRPI с эталоном, допуск ужесточён до 0.01%, чтобы они не сходились: **48 с → 19 с**,
результат тот же (0.381% / 0.207%). На фреймах, которые сходятся с первой попытки, время не меняется.

## Ограничения этой проверки

- Эталоны есть только у 2 фреймов из 14 — у остальных проверялась геометрия (её pixel diff не заменяет).
  Настоящая проверка пойдёт через плагин: он выгружает PNG-эталон для каждого фрейма.
- Пакеты здесь сделаны из `.fig` без Figma (`packages/bench/src/fig2package.js`): векторы — с одной заливкой,
  переопределения в инстансах — частично. Плагин берёт всё это из Figma API напрямую.
- Шрифты Agrandir и Mokoto (мокап Discord) платные и не установлены — текст там рисуется запасным шрифтом.
- В опубликованном шаблоне Physionic нет фотографий — на их месте серые плашки, это не ошибка вёрстки.
