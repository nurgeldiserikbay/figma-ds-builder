# Как проверить самому

Полный цикл на вашем макете: Figma → пакет → дизайн-система и вёрстка → отчёт → переменные обратно в Figma.
Займёт 10–15 минут.

## 0. Что нужно

- **Figma Desktop** (локальные плагины работают только в приложении, не в браузере).
- **Node.js 20+** — `node -v`. Скачать: nodejs.org.
- **Google Chrome** — программа рендерит страницы в нём. Если Chrome стоит не в стандартном месте,
  укажите путь в переменной `CHROME_PATH`.

## 1. Установка (один раз)

```bash
git clone https://github.com/nurgeldiserikbay/figma-ds-builder
cd figma-ds-builder
npm run setup     # зависимости программы + сборка плагина
npm test          # необязательно: тесты программы и плагина (~1 мин)
```

В Figma Desktop: откройте любой файл → *Plugins → Development → Import plugin from manifest…* →
выберите `packages/plugin/dist/manifest.json`. Плагин появится как **«DS Builder — экспорт для вёрстки»**.

## 2. Выгрузка из Figma

1. Откройте свой макет, запустите плагин (*Plugins → Development → DS Builder…*).
2. Выберите область: выделенные фреймы, страница или весь файл. Для первого раза хватит 1–3 фреймов.
3. Масштаб PNG — **1×**.
4. Нажмите **«Пакет для вёрстки»** — скачается `<файл> — ds-package.zip`.
   (**«Только PNG макетов»** — просто картинки всех фреймов, для скриншот-тестов.)

Если плагин написал «Нет PNG для …» — этот фрейм слишком большой для рендера в Figma; он будет свёрстан
и проверен по геометрии, но без попиксельного сравнения.

## 3. Вёрстка и проверка

Проще всего — окно программы:

```bash
npm run ui
```

Откроется страница в браузере: перетащите архив, отметьте React/Vue/ИИ, нажмите «Собрать и проверить».
Ход сборки идёт в окне, готовые сборки (отчёт, дизайн-система, папки React/Vue) — в списке ниже, файлы — в `~/ds-build`.

То же из командной строки:

```bash
npm run ds -- build "~/Downloads/<файл> — ds-package.zip" --out out/my-site --open
```

Что произойдёт:
1. Шрифты макета скачаются из npm (бесплатные Google Fonts). Платные — программа перечислит, их нужно установить в систему.
2. Построится дизайн-система → `out/my-site/design-system/` (`design-system.md`, `tokens.json`, CSS, SCSS, Tailwind).
3. Каждый фрейм будет свёрстан → `out/my-site/<фрейм>/index.html`.
4. Каждая страница сверится с PNG из Figma, при расхождениях — автодоработка.
5. Фреймы одной страницы под разные ширины («Home / Desktop» + «Home / Mobile») соберутся в `out/my-site/home.responsive/`
   и сверятся на ширине каждого макета. Если имена не совпадают — `--group "Главная=Фрейм A,Фрейм B"`.
6. Откроется `report.html`.

Проекты React и Vue (Vite) с компонентами:

```bash
npm run ds -- build "<пакет>.zip" --out out/my-site --framework react,vue
cd out/my-site/react && npm install && npm run dev
```

Имена классов от ИИ: сначала локальная модель ([Ollama](https://ollama.com), `ollama pull qwen2.5-coder:7b`),
затем бесплатные API, если заданы ключи (кончился лимит — следующий). Платный — только с `--ai-paid`.

```bash
export GROQ_API_KEY=…        # необязательно: console.groq.com
export GEMINI_API_KEY=…      # необязательно: aistudio.google.com
export OPENROUTER_API_KEY=…  # необязательно: openrouter.ai, модели :free
npm run ds -- build "<пакет>.zip" --out out/my-site --ai
```

Бесплатные облачные планы могут сохранять запросы: туда уходят имена слоёв и до трёх фрагментов текста из каждого блока.

Только дизайн-система, без вёрстки:

```bash
npm run ds -- analyze "<пакет>.zip" --out out/ds
```

## 4. Что смотреть в отчёте

- **Бейдж** «pixel perfect ✓ / не прошло ✗» по каждому фрейму.
- **Геометрия**: сколько элементов совпали с макетом (±0.5px); список тех, что не совпали.
- **Pixel diff**: доля несовпадающих пикселей — отдельно текст и остальное; **источники расхождений** — какие слои дают больше всего.
- **Наложение** эталона и вёрстки с ползунком и карта различий (красное).
- **Адаптивные страницы**: совпадение на ширине каждого макета; между ними — тянется ли каждый макет, а если нет,
  то почему (например, «текст налезает» или «не на всю ширину: Header»).
- **Раскладка**: «flow, координаты закреплены у блоков: N» — значит, N блоков не сошлись во flex и поставлены по координатам
  (обычно устаревший Auto Layout в макете); остальная страница — на flex.
- Ссылка на **дизайн-систему**.

Откройте и саму вёрстку (`index.html` фрейма) — это обычный HTML/CSS, можно смотреть в DevTools.

## 5. Дизайн-система обратно в Figma

В плагине, блок **«Дизайн-система → Figma»**: выберите `out/my-site/design-system/tokens.json` →
**«Создать переменные и стили»**. Появятся коллекции переменных `DS · Primitives`, `DS · Semantic`
(ссылаются на примитивы), `DS · Typography`, текстовые стили `DS/…` и стили теней. Повторный импорт обновляет, а не дублирует.

## Если что-то пошло не так

Пришлите:
- текст ошибки из терминала;
- для плагина — консоль: *Plugins → Development → Show/Hide console*;
- `out/my-site/report.json` и, если можно, сам `ds-package.zip` (или один проблемный фрейм из него).

## Что пока не умеет

- В React и Vue адаптивная страница только переключается по брейкпоинтам (растягивается — HTML-версия).
- Если в макете не заданы constraints, растяжение между ширинами угадывается по геометрии — проверьте отчёт.
- Плагин проверен на имитации Figma API; первый запуск в настоящей Figma — за вами.
