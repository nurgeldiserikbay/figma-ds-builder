# figma-ds-builder

Автоматизация вёрстки из Figma для макетов любого качества.

- **Плагин Figma** только выгружает данные: PNG-эталоны макетов, дерево слоёв, переменные и стили файла,
  используемые шрифты, векторы и картинки.
- **Платформа** (`ds-build`) делает всё остальное: строит дизайн-систему (токены, семантика, шкалы, аудит),
  верстает страницы на её токенах, сравнивает с макетами и дорабатывает — алгоритмами, а затем ИИ —
  до валидного результата: pixel perfect по геометрии и пикселям.

```
┌─────────── Figma ───────────┐            ┌──────── Ваш компьютер ────────┐
│ packages/plugin             │   пакет    │ packages/builder  (ds-build)  │
│ • эталоны фреймов (PNG)     │ ─────────► │ • дизайн-система и аудит      │
│ • дерево слоёв всех макетов │ JSON + PNG │ • генератор HTML/CSS          │
│ • переменные, стили, шрифты │  + SVG     │ • рендер в Chrome (Playwright)│
│ • векторы, картинки         │            │ • геометрия ±0.5px, pixel diff│
│                             │            │ • автодоработка до эталона    │
└─────────────────────────────┘            └───────────────────────────────┘
```

Формат обмена — [docs/package-format.md](docs/package-format.md).

**Проверить самому:** [docs/how-to-test.md](docs/how-to-test.md) — установка, выгрузка из Figma, вёрстка, отчёт.

```bash
npm run setup
npm run ds -- build "<файл> — ds-package.zip" --out out/my-site --open
```

**Сайт проекта** — `docs/index.html` (GitHub Pages): что за продукт, как работает, установка, работа, результаты.
Включение: *Settings → Pages → Build and deployment → Source: Deploy from a branch → `main` / `/docs` → Save*.

## Принципы

1. **Сначала алгоритм, ИИ — только где без него нельзя.** Всё, что решается детерминированно
   (раскладка, токены, сравнение, подбор поправок), делается кодом: так результат повторяем,
   бесплатен и проверяем. ИИ подключается для задач «на понимание» (семантика тегов, имена классов,
   адаптивность), и его результат всегда проходит ту же проверку с откатом, если стало хуже.
2. **Плагин только выгружает, платформа делает всё остальное.** Плагин ничего не решает за вёрстку:
   он отдаёт полные данные из Figma (PNG, дерево, токены, переменные, стили, шрифты, ассеты).
   Вёрстка, сравнение и доработка — в программе `ds-build`.
3. **Готово = прошло проверку.** Страница не считается готовой без сверки с эталоном из Figma.

## Как понимается «pixel perfect»

Страница считается готовой, только если выполнены оба условия:

1. **Геометрия.** Каждый элемент вёрстки (у него есть `data-figma-id`) измеряется в браузере и совпадает
   со своим слоем в Figma по x, y, ширине и высоте с допуском ±0.5px. Это ловит ошибки раскладки
   даже на 1px и не зависит от того, как браузер рисует шрифты.
2. **Pixel diff** против PNG-эталона из Figma: вне текста — не больше 0.1% пикселей (цвета, фигуры, тени, картинки),
   в тексте — не больше 0.5% (Figma и браузер по-разному растеризуют пары букв; настраивается).
   Расхождения раскладываются по слоям — в отчёте видно, какой слой и сколько пикселей даёт.

Цикл доработки:
1. **Автодоработка.** Для слоёв с наибольшим расхождением программа перебирает поправки (сейчас — интервалы
   и сдвиг строки текста), сравнивает область слоя с эталоном и оставляет только улучшающие. Размеры блоков
   не меняются, геометрия остаётся в силе. Сюда же подключится ИИ: «предложить → проверить → оставить лучшее».
2. Если чистая раскладка (flex) всё равно не проходит, пробуется запасной режим (absolute).
3. Что не прошло — помечается в отчёте с картой расхождений.

Результаты на открытых макетах — [docs/benchmark.md](docs/benchmark.md): на настоящих эталонах Figma
1.98% → 0.38% и 1.68% → 0.21%, геометрия 14/14 фреймов (1 300+ слоёв) без единого промаха.

## Плагин

```bash
cd packages/plugin && npm run build
```

В Figma Desktop: *Plugins → Development → Import plugin from manifest…* → `packages/plugin/dist/manifest.json`.
Кнопки: **«Только PNG макетов»** (zip с PNG по страницам — для скриншот-тестов), **«Пакет для вёрстки»**
(PNG-эталоны + дерево слоёв + векторы + картинки + `fonts.json`, `variables.json`, `styles.json`) и
**«Создать переменные и стили»** — импорт `tokens.json`, который построила платформа, обратно в Figma.

Большой файл (сотни фреймов) плагин выгружает частями по ~25 фреймов. Во время выгрузки окно показывает
номер фрейма из общего числа, полосу и оставшееся время, а если Figma долго готовит один фрейм — пишет, что это
не зависание. Кнопка **«Остановить»** прерывает выгрузку после текущего фрейма; место запоминается, и **«Продолжить
с части N»** доступно даже после закрытия плагина. Старые и новые части программа склеивает в один проект.

Файл можно собирать по кускам: выгрузить страницу компонентов и собрать её, потом выгрузить другую страницу
и нажать у сборки **«дополнить»**. Программа склеит новую выгрузку с пакетом прошлой сборки (он хранится в её папке,
`.package`): прежние экраны возьмутся готовыми из кэша, свёрстаны будут только новые, а компоненты, токены и классы —
общие для всех экранов. Тот же экран в новой выгрузке заменяет прежний. Сборку, которая остановилась с ошибкой,
можно **собрать снова** без повторной выгрузки.

## Быстрый старт (из исходников)

Нужны Node.js 20+ и Google Chrome (или путь к Chromium в `CHROME_PATH`).

Окно программы (выбрать архив, отметить опции, смотреть ход сборки и отчёты; сборки — в `~/ds-build`):

```bash
npm run setup && npm run ui      # из корня репозитория
# после публикации в npm — без клонирования: npx figma-ds-build ui
```

Командная строка:

```bash
cd packages/builder
npm install
npm test                 # тестовый макет → out/sample/report.html
npx ds-build build путь/к/пакету.zip --out out/my-site
# большой файл плагин выгружает частями — передайте все части сразу
npx ds-build build "Файл — ds-package (часть 1 из 12).zip" "… (часть 2 из 12).zip" … --out out/my-site
# дополнить прошлую сборку новой выгрузкой (прежние экраны — из кэша):
npx ds-build build out/my-site/.package "Файл — ds-package.zip" --out out/my-site-2
# свои шрифты (@font-face), если они не установлены в системе:
npx ds-build build пакет.zip --css fonts.css
```

Дизайн-система отдельно (без вёрстки):

```bash
npx ds-build analyze пакет.zip --out out/design-system
```

`tokens.json` (W3C Design Tokens — Tokens Studio, Style Dictionary), `variables.css`, `_tokens.scss`,
`tailwind.config.js`, `design-system.md` (палитра, семантика, типографика, шкалы, аудит контраста WCAG), `analysis.json`.
`build` строит её автоматически, если в пакете нет готовых токенов, и пишет цвета в вёрстке как `var(--color-…)`.

Результат `build`: папка на каждый фрейм (`index.html`, `styles.css`, `render.png`, `reference.png`, `diff.png`),
общий `tokens.css`, `report.html` и `report.json`, папка `design-system/`, адаптивные страницы `<имя>.responsive/`.

Полезные опции `build`:

| Опция | Что делает |
|---|---|
| `--framework html,react,vue` | `html` — чистая папка `html/` (страницы, `css/`, `fonts/`, `assets/`, без служебных атрибутов) — открыть с диска или выложить на хостинг; `react`, `vue` — проекты на Vite с компонентами. Каждый вариант сверяется с рабочей вёрсткой пиксель в пиксель |
| `--group "Главная=Home / Desktop,Home / Mobile"` | явно объединить фреймы в адаптивную страницу (по умолчанию — по именам) |
| `--no-responsive` | не собирать адаптивные страницы |
| `--no-semantic` | только `div`/`span`, без `header`, `nav`, `button`, `h1`… |
| `--ai` | имена классов и безликих экранов от ИИ: Ollama (локально) → Groq → Gemini → OpenRouter (бесплатные планы, если заданы `GROQ_API_KEY`, `GEMINI_API_KEY`, `OPENROUTER_API_KEY`); кончился лимит — следующий; свой сервер — `DS_AI_URL`, `DS_AI_MODEL`, `DS_AI_KEY` |
| `--ai-paid` | разрешить платный провайдер в конце цепочки (`DS_AI_PAID_URL`, `DS_AI_PAID_KEY`, `DS_AI_PAID_MODEL`) |
| `--jobs N` | сколько фреймов проверять одновременно (по умолчанию — по числу ядер, не больше 4) |
| `--no-cache` | пересобрать всё; по умолчанию неизменённые фреймы берутся из кэша (сбрасывается при обновлении программы) |
| `--svg-files` | векторы файлами `<img>`; по умолчанию небольшие SVG вставляются в страницу с цветами из токенов |
| `--layout auto\|flow\|absolute` | режим раскладки; `auto` — flex, а где не сошлось — координаты только у этих блоков |
| `--threshold 0.1`, `--text-threshold 0.5` | допуски pixel diff в % для фигур и текста |
| `--frame <имя>` | собрать только этот фрейм |
| `--no-refine`, `--no-verify` | без автодоработки / без браузерной проверки |
| `--allow-absolute` | разрешить вёрстку экрана целиком на координатах, если она точнее по пикселям (по умолчанию — только когда без неё слои не на своих местах) |
| `--fonts none`, `--css fonts.css` | не скачивать шрифты / подключить свои `@font-face` |

## Как строится дизайн-система

Без ИИ, по всем фреймам пакета — работает и на макетах без стилей, компонентов и Auto Layout:

- **Цвета** — заливки, обводки, текст; почти одинаковые склеиваются по ΔE2000 (почти белые фоны вроде `#FAFAFA`
  сохраняются отдельно), редкие оттенки вливаются в ближайший основной цвет. Семейства по тону (gray, slate, blue…)
  и монотонная шкала 50–950 с учётом тона.
- **Семантика** — background, surface, text-primary/secondary, border, primary, on-primary, accent, статусы:
  по площади фонов, объёму и контрасту текста, обводкам, насыщенности.
- **Типографика** — кегли (±0.5px) → роли h1…h6, body, caption…; варианты по начертанию; семейства; модульная шкала.
- **Отступы** — Auto Layout (точно, вес ×3) и геометрия соседних слоёв; базовая единица (8/6/5/4/3/2), шкала xs…xl.
- **Радиусы, тени, обводки, брейкпоинты**; масштабированные копии экранов (дробные кегли) находятся и не засоряют шкалы.
- **Аудит** — контраст текста к реальному фону под ним (WCAG AA), редкие значения, оценка 0–100.

Проверено против SCSS-переменных автора шаблона Physionic: 14 из 14 совпадений ([docs/benchmark.md](docs/benchmark.md)).

## Как генерируется вёрстка

- **Auto Layout → flex 1:1**: направление, gap, padding, выравнивание, wrap, absolute-дети.
- **Без Auto Layout → вывод по геометрии** (рекурсивный XY-cut): слои, которые не перекрываются,
  раскладываются в колонки и строки с отступами; одинаковые отступы сворачиваются в `gap`.
- **«Прямоугольник + текст» в группе** (кнопки и карточки без Auto Layout): прямоугольник становится
  фоном самой группы.
- **Перекрытия** (бейджи, декор) → `position: absolute` только для этого места.
- **Точечный запасной режим**: если блок не сошёлся с макетом (например, Auto Layout в файле устарел и слои
  раздвинуты руками), координаты закрепляются только у его родителя, при необходимости — уровнем выше;
  остальная страница остаётся на flex. `absolute` для всего фрейма — только в крайнем случае.
- **Векторы и булевы операции** — небольшие SVG вставляются прямо в страницу: правятся в коде,
  цвета, совпавшие с токенами, — `fill: var(--color-…)`; в React — `dangerouslySetInnerHTML`, во Vue — `v-html`.
- **Токены**: цвет, совпавший с токеном, пишется как `var(--color-…, #fallback)`.
- **Одинаковые стили → один класс.**
- **Повороты** — `transform: matrix(…)` от исходного размера слоя; **маски** — `overflow`, `border-radius` или `mask-image`.
- **Семантика** (без ИИ, по правилам): `header`, `footer`, `section`, `nav`, `a`, `button`, `h1–h6`, `p`, `ul/li`,
  `role="img"`; внутри ссылок и кнопок — только `span`, чтобы DOM не ломался. Безликие имена слоёв
  («Frame 12», «Rectangle 3») заменяются на `card`, `icon`, `block`.
- **Поля формы**: подпись над полем — `<label for>`; серый текст или «Введите…» — `placeholder`, тёмный —
  уже введённое `value` (курсор «|» из макета убирается); высокое поле — `<textarea>`; поле со стрелкой и
  «Select…/Выберите…» — выпадающий список (`role="combobox"`, вид как в макете). Фокус с клавиатуры виден.
- **Скроллбар, нарисованный в макете** (узкая дорожка со скруглением и ползунок у правого края блока):
  блок прокручивается (`data-scroll`, системная полоса скрыта), полоса стоит на месте, ползунок едет —
  небольшой скрипт в странице; до прокрутки вид как в макете.
- **Компоненты** — блоки одинаковой структуры (и инстансы Figma) находятся по форме дерева; различия
  становятся пропсами (`label`, `iconSrc`, `rootClass`…). Выводятся в React/Vue.
- **Адаптивность** — фреймы одной страницы под разные ширины («Home / Desktop», «Home / Mobile», «Home 1440»,
  «Главная / Мобильная»; у вариантов должны совпадать хотя бы половина текстов) собираются в одну страницу
  с `@media`. На ширине каждого макета — ровно его проверенная вёрстка (пиксель в пиксель).
- **«Резиновая» вёрстка между макетами** — блоки тянутся по constraints Figma и Fill в Auto Layout; где их нет
  (MIN по умолчанию), по геометрии: на всю ширину и с узкими полями — тянется, широкие поля по центру — контейнер
  фиксированной ширины по центру, явный разрыв в строке («логотип слева, меню справа») — правая часть уходит вправо.
  Проверяется: на ширине макета ничего не сдвинулось, между ширинами нет прокрутки, текст не налезает и не вылезает,
  фоны секций — на всю ширину. Не прошло — этот макет остаётся фиксированным по центру, причина видна в отчёте.
  Уже самого узкого макета — пропорциональное уменьшение. В React/Vue пока только переключение по брейкпоинтам.

## ИИ в программе

Кнопка **«ИИ»** в окне программы — настройки ИИ для имён классов и экранов. Вёрстку ИИ не меняет: всё, что он
предлагает, проверяется, а без ИИ сборка работает так же.

- **Ollama** (бесплатно, на этом компьютере, макеты никуда не уходят). Программа сама видит, установлена ли
  Ollama: если нет — кнопка «Скачать Ollama» для вашей системы и три шага; если установлена, но не запущена —
  кнопка «Запустить Ollama»; модель скачивается кнопкой «Скачать модель». Ollama на другом компьютере — поле
  «Адрес». Очередь: «Ollama первой» или «сначала облако» — на слабом компьютере Ollama подхватывает работу, когда
  кончится облачный лимит (`DS_AI_ORDER=cloud` для командной строки).
- **Пока ни один ИИ не подключён**, у кнопки «ИИ» горит точка, а в окне — подсказка: бесплатный ключ Groq за
  пару минут. Каждый пользователь вводит свои ключи; встроенных ключей в программе нет.
- **Бесплатные облачные планы**: Gemini, Groq, OpenRouter — только ключ.
- **Свой ИИ** — любой сервис, совместимый с OpenAI, по своему ключу: готовые адреса для OpenAI, Anthropic Claude,
  DeepSeek, Mistral, xAI, Together AI, LM Studio и Jan, или любой свой адрес. «Загрузить список моделей» берёт
  модели у самого сервиса. Свой ИИ используется первым.
- **«Проверить»** отправляет каждому подключённому ИИ короткий запрос и показывает, кто отвечает.

С ИИ безликие имена экранов («Desktop - 3») получают понятные («Тарифы») и адрес страницы латиницей
(`/pricing`); имя из Figma остаётся в `AGENTS.md`. Ключи хранятся только на этом компьютере (`~/ds-build/.ai.json`).

## Проект для ИИ-агента

Вёрстка — основа, на которой ИИ-агент (Claude Code, Cursor и т. п.) делает сайт дальше. Поэтому результат
сделан так, чтобы агенту не приходилось тратить токены на шум:

- **Проверка правок по макету — `ds-build check`** (в папке сборки — `./check.sh` и `check.cmd`, в окне
  программы — «проверить правки»). Агент поправил код и сразу видит: расхождение с макетом в процентах, какие слои
  Figma расходятся, где (x, y, размер) и какой элемент кода стоит на их месте (`div.card__image`); картинки макета,
  вёрстки и расхождения — в `.check/<экран>/`. Проверяется `html/` или запущенный проект (`--url
  http://localhost:5173` — React, Vue, любой сайт; страница — адрес#маршрут или `{route}` в адресе).
  Код выхода 0 — всё совпало, 2 — есть расхождения. В `AGENTS.md` — этот цикл и список мест, с которых начинать.
- **`AGENTS.md` в корне сборки** — что здесь код, что эталон, что служебные файлы проверки, и таблица экранов:
  PNG макета, файлы кода, способ раскладки, итог сверки. **`screens/`** — PNG всех макетов с понятными именами.
- **Вёрстка целиком на координатах — только если без неё слои стоят не на своих местах.** Если положение
  слоёв верное, а расходятся пиксели (шрифт, сглаживание, эффекты), код остаётся на flex, а расхождение видно в отчёте.
- **Карта экранов** (`screens.json` и раздел в `AGENTS.md`, без ИИ): переходы между экранами из прототипа
  и ссылок, состояния одного экрана (похожие тексты на той же странице и ширине), общие шапка и подвал.
- **`AGENTS.md`** в папках `html/`, `react/`, `vue/` — карта проекта: страницы и макеты Figma, компоненты с
  параметрами, токены, итог сверки (сколько макетов совпало) и правила работы. Агент читает один файл, а не
  весь проект.
- **Без служебных меток**: `data-name` убраны, `data-figma-id` остаются только у слоёв, к которым привязана
  поправка в CSS.
- **Иконки — в `src/icons.js`** (одинаковые — один раз), в коде — `icons.имя`; **шрифты — в `fonts.css`**.
  Оба файла агенту читать не нужно.
- **Проверка именно отдаваемого кода**: React/Vue-проект рендерится со своим CSS и должен совпасть с
  HTML-версией пиксель в пиксель.

Замер на Physionic (3 фрейма, ~1400 слоёв), React: то, что читает агент, — 624 КБ → 318 КБ (≈160 → 81 тыс. токенов).

## Языки

Сайт, окно программы и плагин переведены на 8 языков: русский (исходный), английский, китайский, испанский,
португальский, немецкий, французский и казахский. Язык выбирается автоматически по браузеру/системе, его можно
сменить в шапке. Отчёты, журнал сборки и памятка для дизайнера пока только на русском.

Как устроено: разметка остаётся на русском, движок `docs/i18n.js` находит тексты на странице и подменяет их
по словарю. Переводы лежат в `tools/i18n/<сайт|app|plugin>.<язык>.json` (русский текст → перевод).

- изменили тексты → `npm run i18n`: заново выгружает тексты со страниц и собирает словари;
- `npm test` (в корне) падает, если на странице появился текст без перевода или словарь не пересобран.

## Дорожная карта

1. Запустить плагин в настоящей Figma, прогнать ваши макеты ([как](docs/how-to-test.md)).
2. Первый выпуск: тег `v0.2.0`, секрет `NPM_TOKEN`, публикация плагина в Figma Community ([как](docs/publishing.md)).
3. Для ИИ-агента: `ds-build verify` — сверка изменённого агентом сайта с макетами (по адресу страницы, для любого
   стека) и MCP-сервер с ней же; компактный CSS (общие наборы flex-свойств); повторы → массивы данных.
4. «Резиновая» вёрстка в React/Vue (сейчас — в HTML) и сопоставление слоёв Desktop и Mobile для общих компонентов.
5. Уточнить правила растяжения и пороги по результатам на рабочих макетах.
