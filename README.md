# figma-ds-builder

Автоматизация вёрстки из Figma для макетов любого качества.

- **Плагин Figma** выгружает всё, что нужно для вёрстки: PNG-эталоны макетов, дерево слоёв, токены и переменные,
  дизайн-систему, стили, используемые шрифты, векторы и картинки.
- **Программа на компьютере** (`ds-build`) верстает из этих данных страницы, сравнивает их с макетами
  и дорабатывает — алгоритмами, а затем ИИ — до валидного результата: pixel perfect по геометрии и пикселям.

```
┌─────────── Figma ───────────┐            ┌──────── Ваш компьютер ────────┐
│ packages/plugin             │   пакет    │ packages/builder  (ds-build)  │
│ • анализ всех макетов       │ ─────────► │ • генератор HTML/CSS          │
│ • дизайн-система, токены    │ JSON + PNG │ • рендер в Chrome (Playwright)│
│ • кандидаты в компоненты    │  + SVG     │ • проверка геометрии ±0.5px   │
│ • эталоны фреймов (PNG)     │            │ • pixel diff + отчёт          │
│ • шрифты, переменные, стили │            │ • автодоработка до эталона    │
└─────────────────────────────┘            └───────────────────────────────┘
```

Формат обмена — [docs/package-format.md](docs/package-format.md).

## Как понимается «pixel perfect»

Страница считается готовой, только если выполнены оба условия:

1. **Геометрия.** Каждый элемент вёрстки (у него есть `data-figma-id`) измеряется в браузере и совпадает
   со своим слоем в Figma по x, y, ширине и высоте с допуском ±0.5px. Это ловит ошибки раскладки
   даже на 1px и не зависит от того, как браузер рисует шрифты.
2. **Pixel diff** против PNG-эталона из Figma: вне текста — не больше 0.1% пикселей (цвета, фигуры, тени, картинки),
   в тексте — не больше 0.5% (Figma и браузер по-разному растеризуют пары букв; настраивается).
   Расхождения раскладываются по слоям — в отчёте видно, какой слой и сколько пикселей даёт.

Цикл доработки:
1. **Автодоработка.** Для слоёв с наибольшим расхождением программа перебирает поправки (сейчас — интервалы
   и сдвиг строки текста), сравнивает область слоя с эталоном и оставляет только улучшающие. Размеры блоков
   не меняются, геометрия остаётся в силе. Сюда же подключится ИИ: «предложить → проверить → оставить лучшее».
2. Если чистая раскладка (flex) всё равно не проходит, пробуется запасной режим (absolute).
3. Что не прошло — помечается в отчёте с картой расхождений.

Результаты на открытых макетах — [docs/benchmark.md](docs/benchmark.md): на настоящих эталонах Figma
1.98% → 0.38% и 1.68% → 0.21%, геометрия 14/14 фреймов (1 300+ слоёв) без единого промаха.

## Плагин

```bash
cd packages/plugin && npm run build
```

В Figma Desktop: *Plugins → Development → Import plugin from manifest…* → `packages/plugin/dist/manifest.json`.
Кнопки: **«Только PNG макетов»** (zip с PNG по страницам — для скриншот-тестов) и **«Пакет для вёрстки»**
(PNG-эталоны + дерево слоёв + векторы + картинки + `fonts.json`, `variables.json`, `styles.json`).
Анализатор дизайн-системы (Design System Extractor) будет объединён с этим плагином.

## Быстрый старт (локальная программа)

Нужны Node.js 20+ и Google Chrome (или путь к Chromium в `CHROME_PATH`).

```bash
cd packages/builder
npm install
npm test                 # тестовый макет → out/sample/report.html
npx ds-build build путь/к/пакету.zip --out out/my-site
# свои шрифты (@font-face), если они не установлены в системе:
npx ds-build build пакет.zip --css fonts.css
```

Результат: папка на каждый фрейм (`index.html`, `styles.css`, `render.png`, `reference.png`, `diff.png`),
общий `tokens.css`, `report.html` и `report.json`.

## Как генерируется вёрстка

- **Auto Layout → flex 1:1**: направление, gap, padding, выравнивание, wrap, absolute-дети.
- **Без Auto Layout → вывод по геометрии** (рекурсивный XY-cut): слои, которые не перекрываются,
  раскладываются в колонки и строки с отступами; одинаковые отступы сворачиваются в `gap`.
- **«Прямоугольник + текст» в группе** (кнопки и карточки без Auto Layout): прямоугольник становится
  фоном самой группы.
- **Перекрытия** (бейджи, декор) → `position: absolute` только для этого места.
- **Токены**: цвет, совпавший с токеном, пишется как `var(--color-…, #fallback)`.
- **Одинаковые стили → один класс** — основа для будущих компонентов.

## Статус

| Часть | Статус |
|---|---|
| Плагин: анализ и дизайн-система | готов, переносится в репозиторий |
| Плагин: PNG макетов + пакет для вёрстки | готов, проверен на имитации Figma API (в Figma ещё не запускался) |
| Программа: генератор + проверка + автодоработка + отчёт | проверена на 5 открытых файлах, см. benchmark |
| Прогон на открытых макетах (`packages/bench`) | готов, воспроизводим |

## Дорожная карта

1. Перенести анализатор дизайн-системы в плагин, запустить экспорт в настоящей Figma.
2. Прогнать на ваших макетах с PNG из плагина, уточнить пороги.
3. Точечный запасной режим: absolute только для узла с расхождением, а не для всего фрейма.
4. Компоненты: повторяющиеся блоки и инстансы → отдельные файлы (HTML-партиалы, затем React/Vue).
5. ИИ-слой (сначала локальная модель через Ollama, затем бесплатные API, платные — по флагу):
   семантические теги, имена классов, адаптивность. После каждого шага ИИ — повторная проверка,
   откат, если pixel perfect сломан.
6. Адаптивность между брейкпоинтами (desktop / tablet / mobile фреймы одной страницы).
