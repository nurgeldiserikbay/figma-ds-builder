# Как подготовить макет в Figma, чтобы вёрстка получилась хорошей

Памятка для дизайнера. Чем чище устроен файл, тем больше DS Builder делает сам, по правилам, без ИИ и без
догадок. ИИ и человеку тоже проще: им не нужно угадывать, что значит «Group 47» и где у кнопки состояние «нажата».

Главная мысль: **макет — это не картинка, а описание интерфейса.** Всё, что дизайнер указал явно (Auto Layout,
компонент, переменная, вариант состояния), программа переносит в код точно. Всё, что видно только глазами,
приходится угадывать.

Проверить файл по этой памятке можно в программе DS Builder: кнопка **«Только проверить макет»** за несколько
секунд покажет, что в файле мешает вёрстке, — с примерами слоёв и ссылками на разделы ниже.

Пометки в конце разделов: **Уже работает** — DS Builder использует это сейчас; **В планах** — данные уже
пригодятся, программа скоро начнёт их использовать.

---

## 1. Auto Layout везде, где элементы выстроены в ряд или колонку

- Кнопка, строка таблицы, карточка, список, меню, форма, секция страницы — Auto Layout.
- Отступы задавайте через **padding** и **gap** Auto Layout, а не пустыми прямоугольниками-распорками.
- Размеры детей: **Fill** — растягивается, **Hug** — по содержимому, **Fixed** — только если размер действительно
  фиксированный (иконка, аватар).
- Свободное размещение (без Auto Layout) — только для того, что правда лежит поверх: бейдж на аватаре, декоративное
  пятно, плавающая кнопка. Для таких слоёв включайте **Absolute position** внутри Auto Layout.

**Уже работает:** Auto Layout становится flex: `gap`, `padding`, выравнивание, перенос строк (wrap). Fill/Hug — растяжение блоков.
Без Auto Layout программа восстанавливает ряды и колонки по координатам — обычно получается, но хуже: код менее
читаемый, а там, где не получилось, блоки закрепляются по координатам.

## 2. Никаких «Group» вместо фреймов

- Группа (Group) — это просто склейка слоёв без отступов и правил. Используйте **Frame** (с Auto Layout).
- Не оставляйте пустые группы, лишние вложенные фреймы «на всякий случай», скрытые старые варианты внутри экрана.
- Скрытые слои (глаз выключен) программа пропускает, но лучше их удалить: они путают и человека, и ИИ.

## 3. Названия слоёв — по смыслу

Имена слоёв становятся именами классов и компонентов в коде. `Frame 1243`, `Group 7`, `Rectangle 12` дают
безликие классы; `card-price`, `header`, `nav` — понятный код.

| Что это | Как назвать слой |
|---|---|
| Шапка, подвал, основная часть | `header`, `footer`, `main` |
| Навигация, меню | `nav` |
| Смысловой блок страницы | `section / Тарифы`, `section / Отзывы` |
| Кнопка | `Button` или имя компонента `Button / Primary` |
| Ссылка | `link` |
| Поле ввода, форма | `input / Email`, `form / Вход` |
| Список и его элемент | `list`, `item` |
| Иконка | `icon / search`, `icon / close` |
| Картинка с содержанием | понятное описание: `Фото команды` — оно станет подписью для экранного диктора |

**Уже работает:** Имена → классы (кириллица переводится в латиницу); `Button`/`btn`/`кнопка` → `<button>`; иконки называются по
слою вокруг (`icon / close` → `icons.iconClose`); названия картинок → `aria-label`.

**Уже работает:** Первое слово имени `header`/`шапка`, `footer`/`подвал`, `nav`/`меню`, `main`, `section`/`раздел`,
`aside`/`sidebar`, `form`/`форма` → соответствующий HTML-тег. Слово отделяйте пробелом или `/`:
`section / Тарифы`, `Header 2`. Имена через дефис (`form-control`, `navbar-brand`) считаются именами классов
и тегом не становятся. Блоки без таких имён программа распознаёт по положению: шапка вверху, подвал внизу.

**Уже работает:** `input`/`поле` → `<input>` (значение в рамке — подсказка), `link`/`ссылка` → `<a>`, `list`/`список` → `<ul>`
с пунктами `<li>`.

## 4. Компоненты для всего, что повторяется

- Кнопки, поля, карточки, строки таблиц, пункты меню, бейджи, аватары — **компоненты**, на экранах — **экземпляры**.
- Не отсоединяйте экземпляры (Detach instance), чтобы «чуть поправить». Нужна разновидность — сделайте вариант.
- Меняющееся содержимое — через **свойства компонента** (Component properties): текст, показать/скрыть
  (boolean), замена иконки (instance swap). Не делайте десять копий карточки, которые отличаются одним словом.
- Наборы вариантов без ошибок: если Figma показывает красное предупреждение у Component Set (например, два
  варианта с одинаковыми значениями свойств) — исправьте.

**Уже работает:** Экземпляры компонента Figma получают общие классы по его имени (`.button`, `.button__label`), даже если копию
переименовали; общие стили — один раз в `components.css`. Повторяющиеся блоки становятся компонентами React/Vue
с параметрами.

**Уже работает:** Свойства вариантов компонента Figma — параметры компонентов React/Vue: `<Button variant="secondary" state="hover">`.
Текстовое свойство и замена иконки (Instance swap) — параметры с именем свойства: `label`, `icon`. В проекте React и Vue
есть каталог компонентов (`#components`): все компоненты во всех вариантах, что встретились в макетах; типы параметров
(какие значения у `variant`) — прямо в коде компонента.

**В планах:** свойство «показать/скрыть» (Boolean) — параметром, который убирает слой.

## 5. Состояния — вариантами компонента

Это важнее всего для «живой» вёрстки, а не копии картинки.

- Каждое интерактивное состояние — **вариант** со свойством `State`:
  `Default`, `Hover`, `Pressed` (или `Active`), `Focus`, `Disabled`, а для полей — ещё `Filled`, `Error`.
- Выбор/переключение — отдельным свойством: `Selected=true/false`, `Checked=true/false`, `Open=true/false`.
- Размеры и виды — тоже свойствами: `Size=S/M/L`, `Type=Primary/Secondary/Ghost`.
- Названия значений — латиницей и одинаково во всём файле (не `Hover` в одном месте и `Наведение` в другом).
- Состояния экрана — отдельными фреймами рядом: пустое состояние, загрузка, ошибка, открытый drawer/модалка.
  Называйте их явно: `Сотрудники / пусто`, `Сотрудники / ошибка загрузки`, `Назначение / шаг 2`.

**Уже работает:** `State=Hover/Pressed/Focus/Disabled` → `:hover`, `:active`, `:focus-visible`, `:disabled` в CSS (и классы
`is-hover`…); остальные свойства (`Type=Secondary`, `Size=L`) → модификаторы `.button--secondary`. Так в HTML, React и Vue.
Варианты, которых нет в макете, программа не придумывает.

**Уже работает:** `Selected`, `Checked`, `Open`, `Current`, `Disabled` (true/false или значение `State`) → атрибуты
`aria-selected`, `aria-checked`, `aria-expanded`, `aria-current`, `disabled`; у чекбокса и переключателя — роль и
фокус с клавиатуры.

**Уже работает:** PNG всех экранов кладутся в `screens/` с понятными именами — агент и разработчик видят все состояния.

## 6. Переменные (Variables) и стили вместо «просто цветов»

- **Цвета** — переменные в коллекции, в два слоя: базовая палитра (`blue/500`, `slate/100`) и смысловые
  (`bg/surface`, `text/primary`, `text/muted`, `border/default`, `action/primary`), которые ссылаются на палитру.
  На слоях используйте **смысловые**.
- **Отступы и радиусы** — тоже переменные: `space/4`, `space/8`, `space/16`…, `radius/sm`, `radius/md`.
  Привязывайте их к padding, gap, радиусу.
- **Текст** — текстовые стили: `Heading/H1`, `Body/M`, `Caption`. Не задавайте шрифт вручную на каждом тексте.
- **Тени** — стили эффектов: `Shadow/sm`, `Shadow/md`.
- Тёмная тема — вторым режимом (mode) коллекции, а не копией экранов.
- Не вводите «почти такие же» значения: `#1E293B` и `#1E293C`, отступ 15 вместо 16. Каждый лишний оттенок
  становится лишним токеном.

**Уже работает:** Переменные (свои и из подключённых библиотек) становятся CSS-переменными с именами из Code syntax; слой,
привязанный к переменной, в коде ссылается именно на неё (`var(--bg-accent)`). Режимы (Light/Dark) — `[data-mode]`.
Текстовые стили → классы типографики (`type-body-medium`), стили эффектов и цветовые стили — тоже токены.
Без переменных повторяющиеся цвета, размеры текста, тени находятся по значениям. Из готовых токенов плагин может
обратно создать переменные в Figma.

## 7. Адаптивность

- Если экран нужен на нескольких ширинах — делайте фреймы для каждой: `Главная / Desktop` (1440),
  `Главная / Tablet` (768), `Главная / Mobile` (375). **Тексты и порядок блоков — одинаковые**, отличаются только
  раскладка и размеры.
- Ограничения (Constraints) для свободно лежащих слоёв: что прижато влево, что растягивается (Left & Right, Scale).
- Шапка и фон на всю ширину — Fill по ширине, контент — с максимальной шириной (Max width) по центру.

**Уже работает:** Экраны одной страницы с общими текстами объединяются в одну адаптивную страницу, которая перестраивается между
ширинами. Fill, Constraints и Max width превращаются в «резиновую» вёрстку; на каждой ширине проверяется, что она
совпадает с макетом и не даёт горизонтальной прокрутки. Если между телефоном и компьютером нет планшетного макета,
анализ макета покажет ряды без переноса, которые на 768px не поместятся, — их стоит нарисовать в планшетной версии
или включить перенос (Wrap). Сама программа такие ряды в колонку не перестраивает: раскладки, которой нет в макете,
она не придумывает.

## 8. Тексты, картинки, иконки

- Текст — настоящим текстом, не картинкой и не контурами (Outline stroke/Flatten). Шрифты — доступные для веба
  (Google Fonts или файлы, которые вы передадите разработчику).
- Высота строки — числом или процентом, одинаковая в рамках стиля. Без «Auto» там, где важно попадание в пиксель.
- Иконки — векторными компонентами одного размера (16/20/24), без лишних невидимых рамок разных размеров.
- Фото и иллюстрации — заливкой (Image fill) фрейма или прямоугольника, а не сотней векторных слоёв.
- Эффекты: размытие фона (Background blur), шум, текстуры браузер рисует иначе, чем Figma. Используйте их там,
  где это действительно нужно, — в отчёте они дают расхождения, которые не исправить кодом.
- Маски — только когда без них никак; обычно хватает «Clip content» у фрейма.

## 9. Прототип и структура файла

- Страницы Figma — по разделам продукта, внутри — экраны по порядку сценария.
- Черновики, старые версии, «Copy», исследования — на отдельной странице `Архив`; её можно не выгружать.
- Связи прототипа: кнопка → экран, ссылка → экран, открытие модалки/drawer (Open overlay). Программа делает из них
  ссылки: **On click → Navigate to** — переход на страницу этого экрана (если он выгружен вместе), **Open link** — адрес,
  **Scroll to** — прокрутка к блоку на странице. Ссылки в тексте (Link) тоже становятся ссылками.
- Поле ввода и кнопка в одном блоке (Auto Layout) — это форма: в вёрстке будет `<form>`, кнопка отправляет её.
- Аннотации Dev Mode и описания компонентов — для правил, которых не видно на картинке: «таблица сортируется по
  клику», «поле обязательное», «максимум 50 символов».

**Уже работает:** **Open overlay** — ссылка на страницу окна (`aria-haspopup="dialog"`), **Close overlay** — возврат назад;
список «кнопка → окно» попадает в `AGENTS.md`, чтобы ИИ-агент сделал из них `<dialog>`. Выгружайте окна вместе с экранами.

**Уже работает:** аннотации Dev Mode и описания компонентов (Description) попадают в `AGENTS.md` проекта — раздел
«Пояснения дизайнера», чтобы ИИ-агент учёл их при разработке.

## Короткий чек-лист перед выгрузкой

- [ ] Ряды и колонки — Auto Layout, отступы — padding/gap, а не прямоугольники-распорки.
- [ ] Нет Group там, где нужен Frame; нет пустых и скрытых слоёв.
- [ ] Слои и компоненты названы по смыслу; нет `Frame 123` на значимых блоках.
- [ ] Всё повторяющееся — экземпляры компонентов, без Detach.
- [ ] Состояния — вариантами `State=…`; состояния экранов — отдельными фреймами с понятными именами.
- [ ] Цвета, отступы, радиусы — переменные; тексты — текстовые стили; тени — стили эффектов.
- [ ] Наборы вариантов без красных предупреждений.
- [ ] Для адаптивных экранов — фрейм на каждую ширину с одинаковыми текстами.
- [ ] Черновики — на странице `Архив`.
- [ ] Текст — текстом, иконки — векторными компонентами, фото — заливкой.

Чем больше пунктов выполнено, тем больше экранов в отчёте DS Builder будут с пометкой «совпадает» и тем меньше
блоков окажется закреплено по координатам.
