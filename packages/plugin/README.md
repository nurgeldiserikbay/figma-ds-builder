# DS Builder — плагин Figma (экспорт для вёрстки)

Выгружает из Figma всё, что нужно программе `ds-build`, чтобы сверстать макеты и сверить их с оригиналом.

## Установка

```bash
npm run build      # собирает dist/
npm test           # сборка + проверка на имитации Figma API (с тестовым макетом)
```

Figma Desktop → *Plugins → Development → Import plugin from manifest…* → `dist/manifest.json`.
Папка `dist/` лежит в репозитории, так что собирать не обязательно.

## Что умеет

| Кнопка | Что получится |
|---|---|
| **Только PNG макетов** | zip: `Страница/Фрейм.png` для каждого фрейма — для скриншот-тестов и сравнения |
| **Создать переменные и стили** | из `tokens.json` платформы: коллекции DS · Primitives / Semantic / Typography, текстовые стили `DS/…` (кегль и интерлиньяж привязаны к переменным), стили теней, по желанию цветовые стили; повторно — обновляет |
| **Пакет для вёрстки** | zip в формате [ds-package](../../docs/package-format.md): PNG-эталоны, дерево слоёв, SVG векторов, картинки, `fonts.json`, `variables.json`, `styles.json` |

Область: выделенные фреймы/секции, все фреймы страницы или всего файла. Масштаб PNG: 1× или 2×.
PNG выгружаются строго в границах фрейма. Плагин ничего не меняет в файле и не ходит в сеть.

## Структура

```
src/export-package.js — сериализация узлов, PNG/SVG/картинки, шрифты, переменные, стили
src/import-tokens.js  — запись tokens.json в переменные и стили Figma
src/main.js           — выбор фреймов, обмен сообщениями с интерфейсом
src/ui.html           — интерфейс и упаковка в zip
build.js              — склейка в dist/code.js (с проверкой на запрещённый в Figma «import(»)
test/mock-run.js      — имитация Figma API: экспорт тестового макета и сверка дерева
test/mock-import.js   — имитация: импорт tokens.json дважды, проверка привязок и отсутствия дублей
```

Анализ дизайн-системы делает платформа (`ds-build analyze`), плагин только выгружает данные.
Плагин только выгружает данные и записывает в Figma то, что построила платформа.
